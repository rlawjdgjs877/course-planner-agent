# 대표 대화 시나리오 3개 (초안 v2)

- 대상 학기: 2026-2, 데모 학생은 가상 인물
- 과목명은 실제, 과목코드·권장 학기·분반 시간·선수과목 관계는 예시. 데이터 정리 후 실제 값으로 교체 (특히 컴퓨터구조 금요일 분반, 시스템프로그래밍 분반 2개는 지어낸 설정)
- 세 시나리오가 서로 다른 경로를 보여주도록 나눔

## 화면 흐름: 폼으로 첫 시간표, 채팅으로 수정

| 단계 | 화면 | 누가 처리 |
|---|---|---|
| 1 | 이수 과목 가져오기 (북마클릿 또는 체크박스), 학년·트랙 선택 | 프론트 |
| 2 | 조건 폼: 목표 학점, 공강 요일, 피할 시간대, 꼭 넣을/뺄 과목. 각 조건에 **반드시 / 가능하면** 토글 | 프론트 |
| 3 | 첫 시간표 생성: 폼 값을 `generate_timetable` 입력으로 바로 변환해 호출 (Claude 거치지 않음) | 백엔드 |
| 4 | 결과 화면: 시간표 3안 + Claude가 쓴 요약 설명 ("전공필수 2과목을 먼저 넣었고, 인문·사회 교양을 채웠어요") | 백엔드 + Claude |
| 5 | 채팅으로 수정·질문 ("1안에서 사회 교양만 바꿔줘", "운영체제 들을 수 있어?") | Claude + 도구 |

- 폼 토글이 강제/선호를 정해주므로, 첫 시간표에서는 Claude가 말을 해석하다 틀릴 일이 없음
- 채팅에서는 "무조건/반드시/싫어/안 돼"는 강제, "웬만하면/가능하면"은 선호로 해석
- 채팅 수정 결과는 화면의 시간표에 바로 반영 (같은 tt_ id 체계)

| # | 시나리오 | 보여주는 것 | 주요 도구 |
|---|---|---|---|
| 1 | 조건 걸고 시간표 짜기 → 일부 수정 | 기본 흐름, 이어지는 대화 | calc_credits, generate_timetable(base_candidate_id) |
| 2 | 불가능한 조건 | 강제/선호 구분, 대안 제시 | generate_timetable(alternatives) |
| 3 | 상위 학년 과목 미리 듣기 | 선수과목 사슬 추적, 스스로 다음 단계 제안 | check_prereq, search_courses, generate_timetable |

## 시나리오 1. 폼으로 첫 시간표 → 채팅으로 교양 하나 바꾸기

**학생:** 2학년, 심화컴퓨팅. 1~2학년 1학기 전공 대부분 이수, 교양 인문·사회 영역 미이수

**대화**

> **폼 입력:** 목표 18학점, 월요일 공강 [가능하면]
>
> **결과 화면의 에이전트 요약:** 지금 전공필수 중 2학년 2학기 권장 과목인 자료구조, 컴퓨터구조가 남아 있고, 교양은 인문·사회 영역이 비어 있어요. 이 넷을 먼저 넣어서 18학점 후보 3개를 만들었어요.
> - **1안 (월요일 공강):** 자료구조, 컴퓨터구조, 전공선택 2과목, 인문 1과목, 사회 1과목
> - **2안:** 1안과 같지만 오전 수업이 하나도 없어요
> - **3안:** 화·목에 몰아서 수요일도 비어요
>
> 세 안 모두 이번 학기 들어야 할 전공필수 2과목을 빠짐없이 넣었어요. 자료구조 002분반은 신청인원이 정원을 넘었던 분반이라 참고하세요.
>
> **학생:** 1안 좋은데 사회 교양을 다른 걸로 바꿔줘
>
> **에이전트:** 1안에서 사회 교양만 바꿨어요. 다른 과목과 시간이 겹치지 않는 사회 영역 과목 중 ○○을 넣었어요. 나머지 5과목은 그대로예요.

**도구 호출 흐름**

| 순서 | 도구 | 주요 입력 | 결과 |
|---|---|---|---|
| 1 | `calc_credits` | `candidate_id: null` | 미이수 전공필수 2개, 부족 교양 인문·사회 |
| 2 | `generate_timetable` (폼에서 직접 호출) | `target: 18`, `credits_strict: false`, `avoid_times: [월 전체]` | `success`, 후보 3개 (tt_001~003) |
| 3 | `generate_timetable` | `base_candidate_id: "tt_001"`, `exclude: [사회 교양 분반 id]`, `ge_areas: ["사회"]` | `success`, tt_004 |

**포인트**
- 폼의 [가능하면] 토글 → `avoid_times`(선호). [반드시]였으면 `free_days`
- 1~2번은 폼 제출 시 백엔드가 호출하고, Claude는 결과를 받아 요약만 씀
- 수정 요청 때 Claude는 바꿀 과목 하나만 넘기고, 나머지 5과목은 백엔드가 유지

## 시나리오 2. 폼 조건으로는 불가능 → 채팅으로 대안 고르기

**학생:** 시나리오 1과 같은 학생

**대화**

> **폼 입력:** 목표 21학점, 금요일 공강 [반드시], 오전(09~12시) 피하기 [반드시]
>
> **결과 화면의 에이전트 요약:** 수강 신청 학점 상한이 19학점이라 21학점은 넣을 수 없어서 19학점 기준으로 찾아봤어요.
> 금요일 공강과 오전 수업 없음을 지키면 **최대 15학점**까지만 돼요. 컴퓨터구조가 금요일 분반밖에 없어서 빠졌어요.
>
> 이렇게 바꾸면 더 채울 수 있어요.
> - **오전 수업을 하루만 허용하면:** 18학점, 컴퓨터구조 포함 (금요일 공강 유지)
> - **금요일 오후 수업을 허용하면:** 19학점, 오전 수업 없음 유지
>
> 어떤 쪽으로 할까요? 15학점 그대로 가도 돼요.
>
> **학생:** 오전 하루 허용으로 해줘
>
> **에이전트:** 화요일 오전에 컴퓨터구조 한 과목만 들어가고, 나머지는 전부 오후예요. 금요일은 비어 있어요. 18학점이에요.

**도구 호출 흐름**

| 순서 | 도구 | 주요 입력 | 결과 |
|---|---|---|---|
| 1 | `generate_timetable` (폼에서 직접 호출) | `max: 21`(백엔드가 19로 제한), `free_days: [금]`, `blocked_times: [월~금 09:00~12:00]` | `partial` 15학점, `omitted_required: 컴퓨터구조(free_day_conflict)`, `alternatives` 2개 |
| 2 | (Claude가 대안을 학생에게 설명하고 선택받음) | | |
| 3 | 대안 시간표 확정 | 대안 tt_alt_001을 그대로 보여줌 (이미 만들어져 있음) | |

**포인트**
- 폼에서 둘 다 [반드시]라 `free_days`, `blocked_times`(강제)
- 학칙 상한 초과는 Claude가 계산하지 않고 백엔드 결과를 그대로 설명
- 조건을 몰래 어기지 않고, 무엇을 풀면 얼마나 좋아지는지 선택지로 제시

## 시나리오 3. "운영체제 미리 들을 수 있어?"

**학생:** 2학년, 운영체제(3학년 권장)를 미리 듣고 싶음

**대화**

> **학생:** 운영체제 이번 학기에 미리 들을 수 있어?
>
> **에이전트:** 지금은 못 들어요. 운영체제는 시스템프로그래밍을 먼저 이수해야 하는데 아직 안 들었어요.
> 시스템프로그래밍은 이번 학기에 2개 분반이 열려요 (화·목 오후, 수·금 오전). 이번 학기에 시스템프로그래밍을 들으면 다음 학기에 운영체제를 들을 수 있어요. 그 뒤로 클라우드컴퓨팅까지 이어져요.
>
> 시스템프로그래밍을 넣어서 시간표를 다시 짜볼까요?
>
> **학생:** 응
>
> **에이전트:** 시스템프로그래밍 화·목 분반을 넣고 18학점으로 짰어요. 전공필수 2과목은 그대로 들어 있어요.

**도구 호출 흐름**

| 순서 | 도구 | 주요 입력 | 결과 |
|---|---|---|---|
| 1 | `check_prereq` | `course_codes: [운영체제]` | `ineligible`, `missing_required: [시스템프로그래밍]`, `chain: 시스템프로그래밍 → 운영체제 → 클라우드컴퓨팅` |
| 2 | `search_courses` | `keyword: "시스템프로그래밍"`, `category: "전공"` | 2개 분반 |
| 3 | `generate_timetable` | `must_include: [시스템프로그래밍]`, `target: 18` | `success` |

**포인트**
- 단순히 "안 돼요"로 끝내지 않고, 선수과목 사슬을 따라가서 이번 학기에 할 수 있는 행동을 제안
- Claude가 결과를 보고 다음 도구를 스스로 고름 (챗봇이 아니라 에이전트인 부분)
- 시스템프로그래밍이 학생 학년보다 위 학년 권장이면, 학생이 동의해서 넣는 것이므로 must_include 예외 규칙 적용

## 시나리오로 확인된 결정 사항

| 항목 | 제안 |
|---|---|
| 첫 시간표 | 조건 폼으로 생성, Claude는 요약만. 강제/선호는 폼 토글로 결정 |
| 채팅 표현 해석 | "무조건/반드시/싫어/안 돼"는 강제, "웬만하면/가능하면"만 선호 |
| 대안 선택 후 | 대안 시간표를 새로 풀지 않고 이미 만든 alternatives 결과를 확정 |
| 데모 학생 데이터 | 가상의 2학년 심화컴퓨팅 학생 1명을 팀이 만들어 고정 (실제 학생 이수내역 사용 안 함) |
